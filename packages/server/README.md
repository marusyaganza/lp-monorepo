# @lp/server

GraphQL backend for the second version of Language Power. It looks words up in the Merriam-Webster dictionaries, stores users and their vocabulary in MongoDB, and generates the data for the learning games.

This package is part of [language-power-v2](../../README.md). Requirements, tool versions and the full local setup are described in the root README; this file covers what is specific to the server.

## Stack

- Node.js 18 (TypeScript compiled to CommonJS)
- Apollo Server 4 mounted on Express 4, with `cors` and `express-rate-limit`
- MongoDB 4.2 / Mongoose 8
- JWT authentication (`jsonwebtoken`) with `bcryptjs` password hashing
- GraphQL schema loaded from `packages/shared/schema`, with resolver types generated by GraphQL Code Generator
- Jest

## How the server runs

The server is written in TypeScript and always runs from compiled JavaScript in `dist/`:

1. `yarn codegen` generates `src/generated/graphql.ts` from the shared schema.
2. `tsc` compiles `src/` into `dist/`.
3. Node runs `dist/server.js`, the `main` entry of `package.json`.

At startup the server reads `.env` with `dotenv`, connects to MongoDB and loads the schema files from `packages/shared/schema` at runtime, so the `shared` package must sit next to the server. It only starts listening after the database connection succeeds; if the connection fails, the error is printed and the server does not serve requests.

### Watch mode

`yarn start` (from the root or this package) runs two scripts in parallel:

- `dev` builds once, then starts nodemon, which restarts the server when files in `dist/` change
- `ts` runs `tsc --watch`, which recompiles `src/` into `dist/` on every change

So editing a file in `src/` triggers a recompile, and the new `dist/` output triggers a restart.

The `dev` script calls `nodemon server.js`, but there is no `server.js` in the package root. nodemon treats the missing file as an argument rather than the script, falls back to the `main` field of `package.json`, and runs `dist/server.js`.

nodemon also reads an optional `nodemon.json` (see `nodemon.example.json`, which only sets what to watch). Keep environment variables in `.env`: anything in an `env` section of `nodemon.json` takes precedence over `.env`, because `dotenv` does not override variables that are already set. An old `nodemon.json` with its own `MONGO_CONNECTION` or an empty `JWT_SECRET` breaks `yarn start` while `yarn start:test` still works.

### One-off run

`yarn start:test` builds the server and runs `node dist/server.js` once, without watching. The root `yarn start:test` and the Cypress workflow use it.

## Environment variables

Variables are loaded from `.env` with `dotenv`. `.env.example` lists them with placeholder values; the root README has a [working `.env` for local development](../../README.md#local-development-setup).

| Variable                                               | Required          | Description                                                                                                                               |
| ------------------------------------------------------ | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                                           | Yes               | Secret used to sign and verify JWTs. Without it, login and signup cannot issue tokens.                                                    |
| `MONGO_CONNECTION`                                     | No                | MongoDB connection string. Defaults to `mongodb://localhost:27017`.                                                                       |
| `PORT`                                                 | No                | Server port. Defaults to `4000`.                                                                                                          |
| `FE_URL`                                               | Yes, for browsers | Frontend origin allowed by CORS, e.g. `http://localhost:8080`                                                                             |
| `USE_MOCKS`                                            | No                | Set to `true` to use saved dictionary responses instead of the Merriam-Webster API. See [Mock dictionary](#mock-dictionary).              |
| `DICTIONARY_API_URI`                                   | Unless mocked     | Merriam-Webster Collegiate Dictionary API base URL, used for English                                                                      |
| `DICTIONARY_API_KEY`                                   | Unless mocked     | Merriam-Webster Collegiate Dictionary API key                                                                                             |
| `DICTIONARY_SPANISH_API_URI`                           | Unless mocked     | Merriam-Webster Spanish-English Dictionary API base URL, used for Spanish                                                                 |
| `DICTIONARY_SPANISH_API_KEY`                           | Unless mocked     | Merriam-Webster Spanish-English Dictionary API key                                                                                        |
| `AUDIO_ENDPOINT`                                       | Yes, for media    | Base URL for pronunciation audio: `https://media.merriam-webster.com/audio/prons`. Also needed with mocks, which contain file names only. |
| `IMG_ENDPOINT`                                         | Yes, for media    | Base URL for dictionary illustrations: `https://merriam-webster.com/assets/mw/static/art/dict`. Also needed with mocks.                   |
| `SALT_NUMBER`                                          | No                | bcrypt cost factor. Defaults to `10`.                                                                                                     |
| `TOKEN_TTL`                                            | No                | Token lifetime in days. Defaults to `7`.                                                                                                  |
| `NODE_ENV`                                             | No                | `production` turns on rate limiting (100 requests per 15 minutes per IP) and disables signup unless `ALLOW_SIGNUP=true`.                  |
| `ALLOW_SIGNUP`                                         | No                | Set to `true` to allow signup when `NODE_ENV=production`. Signup is always allowed outside production.                                    |
| `DEMO_VERSION`                                         | No                | Set to `true` for demo mode. See [Demo mode](#demo-mode).                                                                                 |
| `DICTIONARY_THESAURUS_URI`, `DICTIONARY_THESAURUS_KEY` | No                | Read into the configuration but not used by any feature.                                                                                  |

`AUDIO_ENDPOINT` and `IMG_ENDPOINT` are combined with file names from the dictionary response when a word is looked up, and the resulting URLs are saved with the word. Words saved while they were unset keep broken media links.

## Mock dictionary

With `USE_MOCKS=true`, `searchWord` returns saved Merriam-Webster responses from `src/dictionary/fetchWord/mockFetchWord/mocks` instead of calling the API. Only these queries return a full entry:

- English: `egalitarian`, `fowl`, `heart`, `murther`, `rubber`, `voluminous`, `wheel`
- Spanish: `asi`, `ballena`, `bully`, `caerse`, `ecologista`, `empezar`, `hola`, `idioma`, `instruction`, `llover`, `ser`, `tener`

Any other query returns this list as suggestions, the way the real API suggests spellings for unknown words.

## Demo mode

`DEMO_VERSION=true` configured the former public demo, where visitors could try the app without an account:

- `signUp` and `login` are disabled; the frontend's demo page calls `createDemoUser`, which creates a temporary user
- users and words are removed by MongoDB about 70 minutes after they are created (TTL indexes)
- tokens expire after one hour
- `GET /ping` responds with `OK`, as a health check for the hosted demo

The frontend has its own `DEMO_VERSION` flag that switches the sign-in pages to the demo page.

## API overview

The API is served at `/graphql`. Protected operations expect an `Authorization: Bearer <token>` header with a token from `login`, `signUp` or `createDemoUser`. The schema itself is in [`packages/shared/schema`](../shared/schema).

- **Users:** `signUp`, `login`, `createDemoUser`; query `user`
- **Words:** queries `searchWord`, `word`, `wordsPerPage`, `verbs`; mutations `saveWord`, `updateWord`, `deleteWord`
- **Tags** (experimental feature): query `tags`; mutations `createTag`, `updateTag`, `deleteTag`
- **Games:** queries `games`, `game`, `gameSettings`; mutation `saveGameResult`

`saveGameResult` updates each word's statistics for the game that was played and its spaced-repetition data. `game` then offers the words whose next review date for that game has passed (for conjugation, per tense), optionally filtered by tags. The scheduling is a simplified implementation based on my own Anki settings, not a reproduction of Anki's algorithm.

## Tests

Tests are written with Jest and run with Babel. `src/tests/jestsetup.js` sets mock environment variables and mocks `bcryptjs` and `lodash`, so the tests do not depend on a local `.env`.

Most suites are unit tests and run without a database. These suites read or write MongoDB and need it on `localhost:27017` (`docker compose up -d` from the root):

- the model tests for `User`, `Word` and `WordTag`
- `initDB`, `filterTags` and the `game` and `games` resolver tests
- the game data generator tests for `generateGameData`, `generateSelectDefGame` and `generateSelectWordGame`
- the integration test `src/tests/integration/userWordFlow.test.js`

They use a separate `server-test` database, so they do not touch development data. Without MongoDB these suites wait for the connection and time out.

## Docker

`docker/Dockerfile-server` at the repository root builds the production image: it installs production dependencies for the `server` and `shared` packages, compiles with `yarn build:server`, removes `src/` and runs `node dist/server.js` as the non-root `node` user. The root `docker-compose.yml` uses it in the `app` profile.
