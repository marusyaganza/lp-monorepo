# lp-monorepo

Second version of the Language Power application: a vocabulary trainer for English and Spanish, built as a TypeScript monorepo with a React client, a GraphQL server and a shared design system documented in Storybook. Users look up words in Merriam-Webster dictionaries or add their own, enrich them with examples, images and audio links, and practise them in learning games.

This repository is preserved as a historical project. The application runs locally and the automated tests pass on the pinned toolchain, but dependencies are intentionally frozen and will not be upgraded. Current development focuses on a separate Python/FastAPI iteration.

## Status

- Builds and runs on the pinned toolchain
- Unit, integration and end-to-end tests pass

- Only the Storybook is deployed; the full application is no longer hosted

## Stack

- TypeScript throughout, Yarn workspaces and Lerna
- GraphQL schema shared by all packages, with types generated by GraphQL Code Generator
- React 18, React Router 6 and Apollo Client 3, built with Webpack 5
- Apollo Server 4 on Express 4, with CORS and rate limiting
- MongoDB 4.2 / Mongoose 8
- JWT authentication with `bcryptjs` password hashing
- Storybook 7 for the design system
- Jest and Cypress
- ESLint, Stylelint and Prettier, with Husky and commitlint
- Docker, GitHub Actions, Netlify (Storybook) and Render (historical app deployment)

## Features

- Search English and Spanish words in Merriam-Webster dictionaries and save them to a personal vocabulary
- Add your own words, definitions, examples with translations, and links to images and audio
- Practise the saved words in the games listed below
- A simplified spaced-repetition schedule, based on my own Anki settings, decides which words each game offers next

The spaced repetition is a simplified implementation, not a reproduction of Anki's full scheduling algorithm.

### Games

Each game can be played in Storybook with a fixed set of sample words: Spanish for most games, English for the picture and speaking games. In the application, the games use the words from your vocabulary.

| Game                                                                                                      | Languages        | How it works                                                     |
| --------------------------------------------------------------------------------------------------------- | ---------------- | ---------------------------------------------------------------- |
| [WordEcho](https://lp-design-system.netlify.app/?path=/story/game-gameengine--audio)                      | English, Spanish | Listen to the pronunciation and type the word                    |
| [LexiSense](https://lp-design-system.netlify.app/?path=/story/game-gameengine--select-def)                | English, Spanish | Select the definition that matches the word                      |
| [Definify: Match & Learn](https://lp-design-system.netlify.app/?path=/story/game-gameengine--select-word) | English, Spanish | Select the word that matches the definition                      |
| [WordRecall: Define & Type](https://lp-design-system.netlify.app/?path=/story/game-gameengine--type-word) | English, Spanish | Type the word that matches the definition                        |
| [PictureWord Blitz](https://lp-design-system.netlify.app/?path=/story/game-gameengine--image)             | English, Spanish | Type the name of the object in the picture                       |
| [Conjugation Quest](https://lp-design-system.netlify.app/?path=/story/game-gameengine--conjugation)       | Spanish          | Conjugate a verb in the chosen tense                             |
| [GenderWord Challenge](https://lp-design-system.netlify.app/?path=/story/game-gameengine--gender)         | Spanish          | Choose whether a noun is masculine or feminine                   |
| [VoiceWord Challenge](https://lp-design-system.netlify.app/?path=/story/game-gameengine--speaking)        | English, Spanish | Experimental: say the word that matches the description (Chrome) |

Some games only use suitable words: the listening and speaking games need words with audio, the picture game words with an image, the conjugation game verbs with conjugation data, and the gender game nouns marked masculine or feminine.

### Experimental features

Two features were started but never finished. Their code is still in the repository, but they are not part of the intended experience:

- **Tags.** Words can be tagged, and the vocabulary and games can be filtered by tag. The feature works, but its design was never polished, so it was left out of the version presented as a portfolio project.
- **Speaking game (VoiceWord Challenge).** Uses the browser's speech recognition, works only in Chrome and never ran reliably.

## Requirements

Tool versions are pinned with [Volta](https://volta.sh/) in the root `package.json`, and every package extends them:

- Node.js: `18.17.0`
- Yarn: `1.22.19`

Without Volta, install these exact versions another way (for example with nvm).

It also requires:

- MongoDB 4.2, either with [Docker](https://docs.docker.com/get-docker/) and the included `docker-compose.yml`, or a MongoDB server of your own
- _(Optional)_ [Merriam-Webster API](https://dictionaryapi.com) keys for the Collegiate and Spanish-English dictionaries. With `USE_MOCKS=true` the server uses saved responses instead, so no keys are needed.

## Run the whole app with Docker

The quickest way to try the application. It needs only Docker:

```bash
docker compose --profile app up --build
```

This builds and starts MongoDB, the server and the frontend. Open `http://localhost:8080`, sign up, and search for one of the mocked words, for example `heart` or `wheel` in English, or `hola` or `idioma` in Spanish. The full list is in the [server README](packages/server/README.md#mock-dictionary).

To stop it, use the same profile:

```bash
docker compose --profile app down
```

`down` without `--profile app` only stops MongoDB. The compose file defines no volume, so the data is removed together with the containers.

## Local development setup

1. Install [Volta](https://volta.sh/). Inside the project folder it switches to the pinned Node and Yarn versions automatically.
2. Install dependencies from the lockfile:

   ```bash
   yarn install --frozen-lockfile
   ```

3. Start MongoDB:

   ```bash
   docker compose up -d
   ```

   Wait until `docker compose ps` shows it as `healthy`.

4. Create `packages/server/.env`:

   ```bash
   JWT_SECRET=local-only-secret
   MONGO_CONNECTION=mongodb://localhost:27017/test
   USE_MOCKS=true
   FE_URL=http://localhost:8080
   SALT_NUMBER=10
   AUDIO_ENDPOINT=https://media.merriam-webster.com/audio/prons
   IMG_ENDPOINT=https://merriam-webster.com/assets/mw/static/art/dict
   ```

   `packages/server/.env.example` lists every variable, but its values are placeholders and do not run as they are. The `test` database is the one Cypress uses; Cypress drops it before each test, so do not keep data you care about there.

5. Create `packages/front/.env`:

   ```bash
   GQL_URL=http://localhost:4000/graphql
   ```

6. Generate the GraphQL types and start the server and frontend in watch mode:

   ```bash
   yarn codegen
   yarn start
   ```

   The frontend runs on `http://localhost:8080` and the GraphQL API on `http://localhost:4000/graphql`. Both read their `.env` only when they start, so restart them after changing it.

To browse the design system only, no database or `.env` is needed:

```bash
yarn codegen
yarn storybook
```

Storybook runs on `http://localhost:6006`.

## Scripts

Run from the repository root. Lerna runs the matching script in each package that has one.

| Script                 | Description                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| `yarn start`           | Start the server and frontend in watch mode                                                    |
| `yarn start:test`      | Build and start the server once, and start the frontend; used before Cypress runs              |
| `yarn storybook`       | Start Storybook for `@lp/ui`                                                                   |
| `yarn build-storybook` | Build the static Storybook site                                                                |
| `yarn build:front`     | Generate types and build the frontend into `packages/front/public`                             |
| `yarn build:server`    | Generate types and compile the server into `packages/server/dist`                              |
| `yarn codegen`         | Generate TypeScript types from the GraphQL schema in every package                             |
| `yarn test`            | Run the server's Jest tests                                                                    |
| `yarn cypress`         | Open the Cypress test runner                                                                   |
| `yarn cypress:run`     | Run the Cypress tests headless in Chrome                                                       |
| `yarn lint`            | Run ESLint in every package                                                                    |
| `yarn ready`           | Generate types and apply ESLint and Stylelint fixes                                            |
| `yarn clean`           | Remove build output, generated files and `node_modules`                                        |
| `yarn release`         | Version changed packages and update their changelogs with Lerna (used by the release workflow) |

## Testing

- **Server (Jest):** `yarn test`. Most suites are unit tests; the suites that read or write the database need MongoDB on `localhost:27017` (they use a separate `server-test` database). See the [server README](packages/server/README.md#tests).
- **End-to-end (Cypress):** start MongoDB, create both `.env` files as described above, run `yarn start:test` and wait until the server reports it is ready, then run `yarn cypress:run`. Images and audio from third-party sites are served from local fixtures, so the tests do not depend on those sites. See the [front README](packages/front/README.md#end-to-end-tests).

The UI package has no unit tests; its components are documented and checked in Storybook.

## Docker and deployment

- `docker/Dockerfile-server` and `docker/Dockerfile-front` build the production images. The frontend image is a multi-stage build that serves the static bundle with nginx; the server image runs the compiled server as a non-root user.
- `docker-compose.yml` runs MongoDB on its own, or the whole application with `--profile app`.
- GitHub Actions in `.github/workflows`:
  - `ready.yml` runs lint and tests on pushes to `main` and on pull requests
  - `release.yml`, started manually, runs lint, tests and Cypress, versions packages with Lerna, pushes Docker images to Docker Hub and deploys Storybook to Netlify
  - `deploy-render.yml`, started manually, triggered the Render deploy hooks for the client and server

The application itself is no longer deployed. The state of the repository at the time of the last deployment is tagged [`v2-last-deployed`](https://github.com/marusyaganza/lp-monorepo/tree/v2-last-deployed).
